# Цели — трекер целей (PWA)

Веб-приложение для постановки целей и отслеживания прогресса. Работает в браузере на компьютере
и устанавливается на iPhone через «На экран „Домой“» — без Apple Developer аккаунта. Работает офлайн,
данные хранятся локально в IndexedDB.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5180
npm test           # тесты бизнес-логики
npm run build      # сборка PWA в dist/
npm run preview    # просмотр собранной версии
npm run deploy     # выложить на GitHub Pages
```

## Установка на iPhone

Как и CalorieLens: веб-приложение на экране «Домой», без App Store и без сервера.

1. Открыть <https://arturfeoktystov.github.io/goaltracker/> в **Safari**.
2. «Поделиться» → **«На экран „Домой“»** → «Добавить».
3. Запускать с иконки на экране «Домой» — работает офлайн.

Данные из Safari и из приложения на экране «Домой» хранятся раздельно — пользуйтесь приложением с экрана «Домой».
Данные компьютера и телефона тоже раздельные, пока не подключена облачная синхронизация (см. ниже).

Обновление версии на телефоне: `npm run deploy` — тесты, сборка и публикация `dist/` в ветку `gh-pages`
(GitHub Pages раздаёт её). Приложение на телефоне подхватит новую версию при следующем запуске.

## Архитектура

```
src/
  domain/          чистая логика без зависимостей: типы, даты, расчёт прогресса, статистика
  data/
    store.ts       интерфейс хранилища (Table/Store) — от него зависят сервисы
    dexie/         реализация хранилища на IndexedDB (Dexie)
    service.ts     сценарии: цели, автосоздание дневных задач, ввод прогресса, автозавершение
    index.ts       точка сборки (какое хранилище использовать)
  hooks/           useQuery (реактивные запросы), useToday (смена дня)
  components/      UI-компоненты
  screens/         Сегодня, Цели, Детали цели, Статистика
```

### Ключевые правила

- **Накопительный прогресс** = сумма записей прогресса / целевое значение.
- **Дневной прогресс** = внесённое за день / дневная норма.
- **Процент дня** = выполненные задачи / все задачи дня.
- Для цели с дневной нормой задачи создаются на каждый день от даты начала до дедлайна
  (без дедлайна — на 14 дней вперёд, окно сдвигается при каждом запуске). Id задачи детерминирован
  (`<goalId>_<дата>`), поэтому дублей не бывает.
- Ввод значения в задаче цели создаёт/обновляет **одну** запись прогресса этой задачи, так что дневная
  и общая статистика всегда сходятся. Ручная запись на день, где есть задача, добавляется к задаче.
- Цель автоматически становится «выполненной», когда прогресс достигает целевого значения,
  и возвращается в активные, если прогресс снова опустился ниже (например, удалили запись).

### Как добавить облачную синхронизацию

Все сущности уже имеют поля `updatedAt` и `deleted` (мягкое удаление), а `Table.changedSince(ts)`
отдаёт изменения с момента последней синхронизации. Достаточно:

1. Написать `SyncedStore`, реализующий интерфейс `Store`: читает и пишет в локальный Dexie-store,
   а в фоне отправляет `changedSince(lastSync)` на сервер и применяет входящие изменения
   по правилу last-write-wins по `updatedAt`.
2. Подменить store в `src/data/index.ts`.

Подойдёт любой бэкенд (Supabase, Firebase, свой API) — бизнес-логика и UI не меняются.
